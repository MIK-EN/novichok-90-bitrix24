# Новичок · первые 90 дней

Небольшой прототип для HR и руководителя: карточка новичка, проверки на 7, 30 и 60 день, фиксация препятствия и задача на помощь.

Рабочая доска распределяет новичков по колонкам «Нужна помощь», «Ждут проверки» и «По плану». Нажатие на карточку открывает контрольные точки. Результат «Всё в порядке» сохраняет проверку локально. Для результата «Нужна помощь» нужно написать комментарий и указать срок: кнопка «Добавить задачу в Битрикс24» одновременно фиксирует проверку и создаёт задачу помощи. Если Битрикс24 отклонит запрос, проверка не будет сохранена как выполненная.

## Проверка за 2 минуты: публичное демо

[Открыть демо](https://novichok-90-dg-2026.retroflame3.chatgpt.site/).

Сайт работает с вымышленными данными. Действия сохраняются в `localStorage` браузера. Кнопка «Сбросить демо» возвращает исходные записи. Внешний сервис и реальные данные не используются.

Откройте карточку новичка, выберите контрольную точку, отметьте «Нужна помощь», заполните комментарий и срок. Кнопка создания задачи покажет **демо-задачу только на этом сайте**. Публичный адрес не подключается к Битрикс24 и не создаёт там задачи, даже если у проверяющего есть вебхук. Для проверки настоящей интеграции выполните шаги ниже.

## Проверка реальной интеграции с Битрикс24

Потребуются компьютер с Node.js **22 или новее**, доступ к REST API облачного портала `*.bitrix24.ru` и **входящий** вебхук с правом «Задачи» (`task`). Тест создаёт настоящую задачу в выбранном портале. Используйте тестовый портал или заранее согласуйте создание задачи в рабочем. Вебхук выполняет запросы с правами своего создателя.

1. В Битрикс24 откройте **Разработчикам → Готовые сценарии → Другое → Входящий вебхук**. Назовите его, добавьте право **«Задачи»** и нажмите **«Создать»**. [Официальная инструкция Битрикс24](https://apidocs.bitrix24.ru/local-integrations/local-webhooks.html#%D0%BA%D0%B0%D0%BA-%D1%81%D0%BE%D0%B7%D0%B4%D0%B0%D1%82%D1%8C-%D0%B2%D1%85%D0%BE%D0%B4%D1%8F%D1%89%D0%B8%D0%B8-%D0%B2%D0%B5%D0%B1%D1%85%D1%83%D0%BA). Уже созданный вебхук находится в **Разработчикам → Интеграции → Меню → Редактировать**. Скопируйте его базовый URL вида `https://ваш-портал.bitrix24.ru/rest/123/секретный-код/`. Не добавляйте к нему имя метода (`tasks.task.list.json`) или параметры после `?`.
2. Склонируйте репозиторий и запустите сервер:

   ```bash
   git clone https://github.com/MIK-EN/novichok-90-bitrix24.git
   cd novichok-90-bitrix24
   node --version
   npm start
   ```

   Оставьте терминал открытым. Зависимостей для установки нет. Если порт 4173 занят, остановите другой процесс на нём и повторите `npm start`.
3. Откройте **http://127.0.0.1:4173** на том же компьютере. В верхнем поле вставьте URL вебхука и нажмите **«Подключить»**. Дождитесь надписи **«Битрикс24 подключён»**. На этом шаге сайт проверяет доступ к списку задач; новая задача ещё не создана.
4. Для однозначной проверки нажмите **«Добавить»**, создайте карточку с вымышленным именем и в поле **«Bitrix ID руководителя»** укажите ID пользователя портала, которому можно назначить тестовую задачу. Свой ID можно увидеть в адресе своего профиля Битрикс24: `/company/personal/user/123/` → `123`. ID существующей задачи приёма можно оставить пустым. В открывшейся карточке выберите проверку **7-го дня**, отметьте **«Нужна помощь»**, введите уникальный комментарий и срок, затем нажмите **«Добавить задачу в Битрикс24»**.
5. Успех: в карточке появятся **«Задача #… в Битрикс24»** и **«Подтверждена повторным запросом»**. Откройте ссылку и сверьте название, комментарий и срок в портале. Если повторная проверка не удалась, задача могла быть создана: проверьте её по номеру перед повторной попыткой.

**Важно:** добавление карточки само по себе не создаёт задачу. Для одной карточки на каждой контрольной точке (7, 30, 60 день) задача помощи создаётся только один раз; последующее «Сохранить комментарий» не отправляет новую задачу. В боковой панели должно быть написано «Битрикс24 подключён». Надпись «Демо-задача #…» означает, что запрос в портал не отправлялся.

Если подключение не проходит, проверьте право `task`, права пользователя вебхука, действительность URL и доступность REST API на вашем тарифе. Если новая задача не появилась в общем списке, откройте её по номеру и ссылке из карточки: фильтры списка Битрикс24 могут скрывать задачи.

Секретный URL вебхука вводится только на локальном сайте; он хранится в памяти локального сервера до его остановки, не сохраняется на диск и не включён в репозиторий. Не публикуйте URL в GitHub, скриншотах или переписке. Сервер доступен только на `127.0.0.1:4173`. Для удалённой проверки каждый проверяющий запускает его на своём компьютере со своим вебхуком.

Альтернатива вводу в форму — переменная окружения `BITRIX_WEBHOOK_URL`, если она уже настроена в безопасном окружении.

Локальный режим связывает карточку с существующей задачей приёма по её ID: проверяет задачу через `tasks.task.get`, показывает название и ссылку. Если отмечена проблема, создаёт задачу через `tasks.task.add`. Новичков из всех задач автоматически не ищет, поскольку формат задач приёма в компании не указан. Исходящие вебхуки и фоновая синхронизация в этом прототипе не используются.

Чтобы показать реальный результат, в локальном режиме откройте карточку Марии Лесковой, выберите проверку на 7-й день и нажмите «Добавить задачу в Битрикс24». Сервер создаст задачу и повторно прочитает её по ID. В карточке появятся номер задачи, ссылка на портал и отметка о подтверждении. Откройте ссылку в Битрикс24, чтобы увидеть задачу там. Если повторное чтение не удалось, номер и ссылка сохранятся: проверьте задачу в портале, прежде чем пытаться создать новую.

## Проверка

`npm test` проверяет даты контрольных точек, сохранение проблемы, построение задачи помощи, REST-запросы и серверные ответы. Основной сценарий демо дополнительно проверяется в браузере.

В проекте настроен минимальный CI на GitHub Actions. При каждом push и pull request он запускает `npm test` на Node.js 22. Это базовая автоматическая проверка изменений: результат виден до слияния и помогает вовремя обнаружить ошибки в проверяемом поведении.

## Ограничения

Демоданные не служат основанием для кадровых решений. Сервис не оценивает KPI и не назначает бонусы: причины ранних увольнений неизвестны. Локальные записи хранятся только в браузере; для командного использования нужны авторизация и общее хранилище.
