# Новичок · первые 90 дней

Небольшой прототип для HR и руководителя: карточка новичка, проверки на 7, 30 и 60 день, фиксация препятствия и задача на помощь.

Рабочая доска распределяет новичков по колонкам «Нужна помощь», «Ждут проверки» и «По плану». Нажатие на карточку открывает контрольные точки. Результат «Всё в порядке» сохраняет проверку локально. Для результата «Нужна помощь» нужно написать комментарий и указать срок: кнопка «Добавить задачу в Битрикс24» одновременно фиксирует проверку и создаёт задачу помощи. Если Битрикс24 отклонит запрос, проверка не будет сохранена как выполненная.

## Публичное демо

[Открыть демо](https://novichok-90-dg-2026.retroflame3.chatgpt.site/).

Сайт работает с вымышленными данными. Действия сохраняются в `localStorage` браузера. Кнопка «Сбросить демо» возвращает исходные записи. Внешний сервис и реальные данные не используются.

В демо кнопка создания задачи показывает учебную задачу внутри интерфейса. Она не отправляет данные в Битрикс24; об этом есть подсказка рядом с кнопкой.

## Локальный режим с Битрикс24

Нужен Node.js 22+, портал Битрикс24 с доступом к REST API и входящий вебхук с разрешением `task`. Вебхук действует с правами создавшего его пользователя. Запустите `npm start`, откройте `http://127.0.0.1:4173` и вставьте URL вебхука в локальную форму. Альтернатива: переменная окружения `BITRIX_WEBHOOK_URL`. Сервер слушает только `127.0.0.1:4173`, а секрет не отдаёт в браузер и не сохраняет на диск. Адрес вебхука не следует помещать в код, коммит или скриншоты.

Локальный режим связывает карточку с существующей задачей приёма по её ID: проверяет задачу через `tasks.task.get`, показывает название и ссылку. Если отмечена проблема, создаёт задачу через `tasks.task.add`. Новичков из всех задач автоматически не ищет, поскольку формат задач приёма в компании не указан. Исходящие вебхуки и фоновая синхронизация в этом прототипе не используются.

## Проверка

`npm test` проверяет даты контрольных точек, сохранение проблемы, построение задачи помощи, REST-запросы и серверные ответы. Основной сценарий демо дополнительно проверяется в браузере.

В проекте настроен минимальный CI на GitHub Actions. При каждом push и pull request он запускает `npm test` на Node.js 22. Это базовая автоматическая проверка изменений: результат виден до слияния и помогает вовремя обнаружить ошибки в проверяемом поведении.

## Ограничения

Демоданные не служат основанием для кадровых решений. Сервис не оценивает KPI и не назначает бонусы: причины ранних увольнений неизвестны. Локальные записи хранятся только в браузере; для командного использования нужны авторизация и общее хранилище.
